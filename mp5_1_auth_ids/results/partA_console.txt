--- Lab task 1: replay attack ---
   legitimate run accepted by network: True
   attacker replays captured (RAND, RES) to a STATELESS network: accepted = True  <-- replay works
   attacker answers a NEW RAND with the captured RES        : accepted = False
   [used-RAND tracking] legitimate run: (True, 'response matches')
   [used-RAND tracking] replayed (RAND, RES): (False, 'RAND already used (replay rejected)')
   [used-RAND tracking] answer to a RAND never issued: (False, 'RAND was never issued by this network')
   Parallel with real AKA: the network binds each challenge to a sequence number (SQN) carried in AUTN;
   the SIM rejects a stale SQN, so a recorded RAND/AUTN cannot be replayed to the device either.

--- Lab task 3: network proves itself to the device (AUTN-like token) ---
   genuine network: device accepts token = True
   rogue base station (no K) sends its own token: device accepts = False
   GSM A3 authenticated only the SIM to the network, so a fake BTS could impersonate the network;
   UMTS AKA adds AUTN so the device also verifies the network.

--- Lab task 4: ways this scheme simplifies real 5G AKA ---
   1. No SUCI: the subscriber identity (SUPI/IMSI) would be sent in clear; 5G conceals it with ECIES public-key encryption of the SUPI.
   2. No standardised MILENAGE/TUAK: a generic HMAC-SHA256 stands in for f1-f5 (RES, CK, IK, AK, MAC).
   3. No sequence number / AUTN structure: replay protection here is a used-RAND list, not SQN + AMF + MAC-A with window checks.
   4. No anonymity key (AK) hiding the SQN and no AUTS resynchronisation procedure after a sync failure.
   5. No key hierarchy: real 5G derives K_AUSF -> K_SEAF -> K_AMF -> K_gNB / NAS keys (and separate user-plane keys); here one session key.
   6. No serving-network binding (SNN) in key derivation and no home-network control of the final confirmation (5G AKA / EAP-AKA').
